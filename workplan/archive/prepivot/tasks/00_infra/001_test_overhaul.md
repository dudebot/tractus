## Context

The legacy C++ articulator-synthesis dependency was removed (commit `e522308`,
2026-05-04), and the project pivoted to a five-module physics-first
architecture. The test suite needs an overhaul because (a) several
tests are tied to the deleted upstream oracle, (b) several test
fp64-by-default assumptions that no longer hold, and (c) the new
architectural invariants (GestureEvent composition, wall-param
anatomy-static enforcement, frication physical derivation,
non-circularity rule on body-model training, channel-model
identifiability, cheat-channel ablation) have **zero coverage**.

Read before starting:
- `../../ARCHITECTURE.md` §3 (identifiability ledger), §6 (memory
  gates), §10 (validation discipline), §16 (CI guardrails checklist).
- The 2026-05-04 test-audit report findings, summarized inline below.

**New tests required (coverage gaps, ranked):**
1. **GestureEvent composition / async overlap** (CRITICAL). Two
   overlapping gestures on different channels, or partially
   overlapping on same channel, must compose to a continuous body
   state within reachability.
2. **Wall-param anatomy-static enforcement** (HIGH). Assert wall
   params have shape `[93]` sourced from anatomy (per ARCH §487-494,
   §510-515), `wall_dynamic_residual` defaults OFF and is
   energy-capped, and no free `[T,93,3]` per-frame wall channel
   exists in any code path.
3. **Frication physical derivation** (HIGH). Zero constriction-area
   → zero frication gain mathematically (not learned). Additionally
   assert that `frication_color` cannot synthesize frication when
   constriction + pressure don't physically support it (ARCH §516-524,
   §1684-1685). Disabling color residual changes loss in 5–20%
   Goldilocks range.
4. **Channel-model identifiability ablation** (HIGH). Register the
   marker + placeholder; the actual ablation gate (with calibrated
   threshold) is owned by infra/002 and pretraining/004.
5. **Non-circularity placeholder** (MEDIUM). Register the marker;
   the lint/grep gate is owned by infra/002.
6. **Cheat-channel ablation placeholder** (MEDIUM). Register the
   marker; the 5–20% Goldilocks gate is owned by infra/002.
7. **fp32 default** (MEDIUM). Assert `jax_enable_x64` is False in
   non-parity paths; only opt-in for parity.
8. **GestureEvent dataclass contract** (MEDIUM). Round-trip
   serialization, temporal-ordering invariants.

## Deliverable

1. **Retire** the two files / functions named above. Delete or skip
   with a clear message pointing to this task.
2. **Re-tool** the four parity tests to use saved fixtures. If a
   frozen pre-deletion fixture is missing, mark the test
   `@pytest.mark.xfail(strict=True, reason="missing frozen

   regenerated by correctness/002.

   above. Place under `tractus_engine_advanced/tests/` or
   `tractus_controller/tests/` per concern. Use `pytest` markers
   (`@pytest.mark.parity`, `@pytest.mark.fp32_default`, etc.) so the
   test suite can be sliced.
4. **Register SOTA markers only** (no implementations here):
   `gradient_fd`, `energy_conservation`. Full implementations land in
   correctness/003 and correctness/002.
5. **Update `pyproject.toml` / `pytest.ini`** to register markers
   and make `pytest -q` run only fp32-default tests by default;
   `pytest -q -m parity` for the parity suite; etc.
6. **Document** the test taxonomy in
   `tractus_engine_advanced/tests/README.md` + `tractus_controller/tests/README.md`.

## Acceptance gates (automated, no user input)

- ✅ `pytest -q` (default) passes on a fresh checkout. Counts:
  - retired tests removed.
  - re-tooled tests skipped with explicit message if fixtures
    missing, else passing.
  - new architectural-invariant tests present with at least
    `xfail` markers if implementation work blocks them.
- ✅ `pytest -q -m parity` runs only the parity-suite tests, all
  using saved-fixture oracle.
- ✅ `pytest -q -m fp32_default` confirms `jax.config.x64_enabled`
  is False.
- ✅ The eight new architectural-invariant tests exist (file paths
  reported in JSON) and at minimum have `xfail` markers if the
  feature isn't built yet.
- ✅ All `xfail` placeholders use `strict=True` and the reason names
  the blocking task ID (e.g., `correctness/004` for frication tests).
- ✅ Parity / fp64 tests run in an isolated subprocess and cannot
  flip the default `jax_enable_x64` state of any other test.
- ✅ `pytest --collect-only` (default slice) shows the kept
  pure-linguistic and pure-math tests still collected (not silently
  filtered out by marker rules).
