# tractus_engine_advanced — test taxonomy

Owner: `infra/001`. This file documents *what each test slice covers*
and *how to run it*. Markers are registered in
`pyproject.toml::[tool.pytest.ini_options]`.

## Quick reference

| Slice                                              | Command                                                                  |
|----------------------------------------------------|--------------------------------------------------------------------------|
| Default (fp32-default; safe in any process)        | `pytest -q`                                                              |
| Parity (fp64 opt-in; **subprocess-isolated**)      | `python -m tests._parity_subprocess_runner` (or `python tests/_parity_subprocess_runner.py`) |
| One-marker filter (e.g. only fp32-default checks)  | `pytest -q -m fp32_default`                                              |
| Collection sanity                                  | `pytest --collect-only`                                                  |

## Slice semantics

### `parity` and `fp64_oracle`

Tests that **must** run with `jax_enable_x64=True`. Saved-fixture
parity against the legacy fp64 oracle lives here. Per
`ARCHITECTURE.md` §10 + `infra/001`, these are excluded from the
default slice (`addopts = -m 'not parity and not fp64_oracle'`) and
only the `_parity_subprocess_runner.py` driver re-includes them — in a
**child process**, so `jax_enable_x64=True` cannot leak into another
test's process.

### `fp32_default`

Pin against drift back to fp64-by-default. Asserts
`jax.config.x64_enabled is False` and `jnp.array([1.0]).dtype == fp32`.

### Architectural-invariant markers (placeholders)

These tests are written today and `xfail(strict=True)` against the
component that owns the implementation. When the component lands, the
test flips to pass without rewriting.

| Marker                       | Coverage gap                                       | Blocked by                              |
|------------------------------|----------------------------------------------------|-----------------------------------------|
| `gesture_event`              | composition / async overlap / dataclass contract   | `correctness/004`, `pretraining/003`    |
| `wall_static`                | wall params anatomy-static; residual default-OFF + capped | `correctness/004`                |
| `frication_physical`         | zero-area→zero-gain; color cannot synthesize       | `correctness/004`                       |
| `channel_identifiability`    | speaker-encoder ablation gate                      | `infra/002`, `pretraining/004`          |
| `non_circularity`            | body-model not trained through TEA audio loss      | `infra/002`                             |
| `cheat_channel`              | wall-residual + frication-color Goldilocks gate    | `infra/002`                             |

### SOTA marker placeholders (no implementation here)

## Frozen fixtures, not live oracles

New tests must use the `fixture_oracle` marker and consume only frozen
fixtures from `outputs/fixtures/` — never a live oracle. Frozen
fixtures are not regenerated by `correctness/002`; they are the
surviving oracle
(ARCH §1028-1030).

## Why subprocess isolation for parity

If a single test in the run flips `jax.config.update("jax_enable_x64", True)`,
every later test in the same process sees fp64 silently. That defeats
the whole point of `fp32_default`. Hence: parity tests run in a child
process driven by `_parity_subprocess_runner.py`; the in-process
default loop skips them with a pointer to the runner.
